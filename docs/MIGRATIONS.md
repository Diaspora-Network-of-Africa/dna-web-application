# Migrations: the route from a committed file to the canonical project (handoff 62-MIG, ruling 1827)

1. Code commits the migration file, `supabase/migrations/{version}_{name}.sql`, before anything applies it (225); an applied file is never amended, a change is a new file (466).
2. Chat dry-runs the file and reads it against the tree; a file that adds an enum value and uses it is two files, applied in two runs.
3. Code dispatches a rehearsal: `gh workflow run migrate.yml -f mode=rehearse -f version=<14 digits> -f ref=<full 40-character sha>`; the workflow and `scripts/migrate.sh` run from `main`, and only the migration file is read out of that commit, by `git show`, its blob hash checked.
4. The founder approves the run in GitHub (the `canonical-migrations` Environment, its required reviewer); the run refuses, red with its reason, a missing or duplicate file, a ref on no branch, a version already in the ledger or not later than its head, or a file carrying its own `begin;` or `commit;`.
5. Rehearse runs the ledger row and the file in one transaction, checks the ledger's md5 against the file's, and rolls back; it writes nothing.
6. Code dispatches `apply` with the same version and ref; the founder approves it; apply commits the same transaction, then reads the ledger md5 back on a fresh connection and prints it with the file's sha256 and md5, the actor and the approver.
7. Chat reads `supabase_migrations.schema_migrations` back and compares the md5 with the file's; then the PR merges promptly, because `tests/migration-drift.cjs` is red on every other branch from apply to merge (G58).
8. The database URL is the Environment's secret `MIGRATE_DB_URL`, a direct or session connection string for the migrate role; no other workflow references it, and `tests/migrate-workflow.cjs` fails `pages.yml` if one does or if `migrate.yml` gains a `push` or `pull_request` trigger. Never `supabase db push`, never the Supabase MCP's `apply_migration` (553), never a ledger row outside the transaction that runs the file. When the workflow is down, the fallback is the founder's SQL Editor paste of a script Chat generates from the committed bytes, ledger row and file in one transaction (1827).
